# Второй отложенный набор: запросы от людей вне проекта

Зачем. Первый отложенный набор (`tasks/heldout.jsonl`) написал тот же человек, что правил промпт агента: 73 из 100 задач на один инструмент, 7 состояний трека. Чтобы оценке можно было верить, нужны запросы, которые сформулировали другие люди, и эталоны, которые независимо друг от друга разметили двое. Этот каталог — инструменты и правила для такого сбора.

## Что лежит здесь

| Файл | Что это |
| --- | --- |
| `cards.jsonl` | 25 карточек ситуаций на 14 состояниях трека, ru и en. Карточка описывает, что у человека есть и чего он хочет, но не называет действия: слова вроде «отдели», «вокал», «обрежь», «денойз», «BPM» запрещены, тест это проверяет |
| `../collect.py` | анкета для участника, импорт ответов, сведение двух разметок |
| `LABELING.md` | инструкция разметчика: что размечаем, правила для спорных мест, синтаксис, примеры |
| `drafts/` | сырые ответы, черновики задач, листы разметки. **В git не идёт**: там свободный текст людей |

## Порядок

1. **Участники.** Не меньше 15 человек вне проекта, разные: музыканты, подкастеры, люди, которые просто пишут голосовые. Хотя бы треть пишут по-английски или на другом языке. Не привлекать тех, кто видел промпт агента, README бенчмарков или задачи из `tasks/`.
2. **Анкета.** Каждому своя: `uv run python benchmarks/agent/collect.py questionnaire --participant P07 --lang ru > p07.md`. В ней 12 случайных карточек в случайном порядке (стабильно для одного участника) и вступление с согласием. Анкету можно отдать файлом или перенести в Google Forms: тогда на выходе нужен CSV с колонками `participant, card, request`. Список инструментов, интерфейс `ah ui` и примеры ответов участникам **не показываем**: иначе они начнут писать нашими словами.
3. **Импорт.** `uv run python benchmarks/agent/collect.py import responses.csv`. Участники заменяются на P01, P02… (исходные имена и почты не сохраняются), повторы внутри одной карточки выкидываются, язык определяется по тексту. На выходе `drafts/tasks.draft.jsonl` и два одинаковых листа `drafts/label_A.csv` и `label_B.csv`.
4. **Проверка анонимности.** До разметки прочитать черновик глазами и вычистить имена, телефоны, адреса, если они всё-таки попали в текст.
5. **Разметка.** Разметчики: **A — владелец** (`drafts/label_A.csv`), **B — Джамаль** (`drafts/label_B.csv`). Каждый записывает ожидаемый план **в своём листе и не глядя в чужой**, по общей инструкции [`LABELING.md`](LABELING.md): правила для спорных мест и примеры. Промпт агента правил не разметчик, а Claude Code. Синтаксис колонок описан там же и в начале `collect.py`: `accept` (варианты плана через `|`, шаги через `>`, `-` если инструменты не нужны, `*` если запрос двусмысленный), `inputs`, `params`, `needs` (что `analyze` обязан не выключать), `unsupported`, `reply_any`, `forbid`. Состояние трека смотреть в `fixtures/<fixture>.json`.
6. **Сведение.** `uv run python benchmarks/agent/collect.py merge drafts/label_A.csv drafts/label_B.csv`. Совпавшие эталоны (порядок вариантов не важен) попадают в `tasks/heldout2.jsonl`. Расхождения уходят в `drafts/disagreements.csv`, их разбирают вдвоём и записывают решение в `resolved.csv` (тот же формат листа), потом `merge ... --resolved resolved.csv`. Каждый эталон проходит настоящий `validate` агента; негодные выводятся списком. Скрипт печатает согласие разметчиков: долю полностью совпавших эталонов и каппу Коэна по классу плана. Если каппа ниже 0.6, правила разметки неясны: их надо уточнить и разметить заново, а не прогонять бенч.
7. **Заморозка.** Закоммитить `tasks/heldout2.jsonl` до первого прогона. Хэш коммита и sha256 файла попадут в `summary.json`.
8. **Прогон.** Один раз на модель, без правок промпта, скорера и эталонов между прогонами:
   `uv run python benchmarks/agent/run.py --tasks benchmarks/agent/tasks/heldout2.jsonl --model ... --out benchmarks/results/agent-heldout2-<model>`, затем `score.py --out ...` и `execute.py ...`. Найденные ошибки скорера или эталона исправлять отдельно и показывать обе цифры.

## Сколько нужно

Чем больше задач, тем уже интервал. При доле верных планов около 0.9 интервал Уилсона по задачам даёт примерно ±6% на 100 задачах, ±5% на 150, ±4% на 250. Цель — **не меньше 150 задач после сведения**: 15 человек × 12 карточек = 180 ответов, часть уйдёт на повторы и расхождения. Ответы одного человека похожи между собой, поэтому участников лучше больше, а карточек на человека меньше. В отчёте интервал можно считать бутстрэпом по участникам (поле `participant` в задачах).

## Что этот набор не покрывает

- Агент видит только метаданные трека, аудио участники не загружают. Сквозная проверка качества на настоящем аудио — отдельная задача (задача 8 плана).
- Карточки всё равно написаны нами, и выбор ситуаций — наш. Живые запросы из `ah ui` (с согласия пользователей, с локальным логом запроса и `track_data`) были бы следующим шагом. Это изменение продукта и решение про приватность, его принимает владелец.
